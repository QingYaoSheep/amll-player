## 验证方法与假设

修复前固定提交 `b659a1966421cbde1bdba54ef3cacefc9da1abc3` 的 [测试运行](https://github.com/QingYaoSheep/amll-player/actions/runs/37214915088) 使用真实视频：在紫色底层上呈现不透明度 0.65 的视频，关闭/开启最大半径模糊，比较上沿零半径处的真实屏幕 RGB。另检查当前调度频率及倒影顶端的真实 CAGradientLayer 遮罩。初次测试提交 `b9993b11` 因测试中的可选 Float 类型未解包而编译失败，不将其作为故障复现证据。

运行已完成：461 项单元测试有 6 条失败断言，8 项 UI 零失败。其中 5 条属于新回归：上沿颜色通道 45→84、76→136，调度频率 30 而非 60，倒影图像和可见遮罩的顶端 alpha 均为 3 而非至少 250。另一条是既有暂停恢复测试把异步播放器层就绪状态与诊断快照直接比较的观察竞态，单独记录，不算作本次边界故障。修正该断言为检查辅助像素失效前后的主视频状态不变，保留真实播放器就绪、item/output 身份、暂停及恢复检查。

Apple 测试无法在 Windows 本地执行。为避免阻断工程准备，修复前测试在不可变提交上继续运行，同时准备候选修改；最终同时记录前后运行结果，不以源码推测代替红色结果。

待检验的因素分别为：Core Image 默认线性工作空间与下层 SDR 合成的上沿色差；30Hz 串行大图回传造成的输出等待；倒影截图来自异步旧图像。色差回归不从压缩截图推断精确 alpha，也不宣称覆盖用户全部在线封面。

## 实现

- 模糊使用显式 sRGB 工作/输出空间；实际半径仍从顶部零值平滑增加，不新增整层透明度渐变，不降低现有 1.5 渲染缩放或半径。
- 串行后台队列直接把 Core Image 输出编码到 Metal drawable；最多两个提交在途，忙碌帧不排队旧输入。仅测试主动请求时对真实目标纹理做一次 GPU blit 读回，生产显示不走此路径。
- 当前视频像素直接构造视频和倒影输入，保留两者现有几何、媒体渐隐、透明度及真实层序。暗度使用同色平面，省去一份大图捕获；其他实际下层（包括 Metal 背景和额外视图）继续按真实层级采样。
- 沉浸取帧及模糊调度目标 60Hz，普通方形封面保留原 30Hz 取帧设置。过期资源、配置、离屏及后台结果不能提交；进入后台前停止新提交并确保已提交工作已调度。
- 废弃画面保持透明至当前代次的新 GPU 输出成功，避免重新露出旧 drawable。设备显示 FPS/帧龄来自 drawable 呈现时间，GPU 耗时来自命令完成，分别统计；样本最多 120 条，不含 URL 或账号数据。模拟器 SDK 不提供 drawable 呈现回调，单独记录并明确标为“模拟器完成率”，不冒充设备 FPS；画面回归仍读取真实目标纹理和窗口像素。
- 倒影遮罩从顶端 alpha 1 开始，删除顶端淡入，保留下方已有衰减点和底部透明终点。
- 用户补充倒影拉长：原实现把底部 24% 小片段按独立横纵比例铺满倒影区域。改为完整源图等比垂直镜像，源图底部紧接倒影顶端，只裁切可见长度；超出完整镜像的区域透明。可见倒影和模糊合成继续共用同一映射，保留现有位置、高度、透明度和帧所有权。Windows 无 Core Image 执行环境，此补充先接入真实图像回归，再随最终提交验证，不将静态比例分析记录为修复前 Apple 渲染测试通过。
