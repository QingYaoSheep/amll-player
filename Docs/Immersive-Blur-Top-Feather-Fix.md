## 确认的方案

- 最上沿的模糊呈现完全透明，直接露出实际下层画面；向下用 `t²(3−2t)` 恢复原有整层不透明度，两端斜率为零。
- 默认顶部透明羽化长度为 24pt，可在现有沉浸调试面板调整为 0–80pt、步进 1pt。0 关闭。实际生效长度不超过原有向上模糊渐变区域。
- 羽化终点以下维持原有半径及混合比例直到屏幕底部。视频隐藏、尚未呈现或退化为全背景模糊时，不应用该局部羽化。零模糊及减少透明度仍关闭模糊层。
- 保留所有视频底部渐隐、等比镜像倒影、背景暗度、真实层序与清晰控件。色差、帧差和合成差异继续独立检查，不把截图归因于单一原因。

## 实现与兼容

`ImmersiveBackgroundBlurProfile` 统一提供有效长度及透明度采样；半径曲线数学结果保持不变。`ImmersiveArtworkVisibility.blurMask` 使用静态 `CAGradientLayer` 表示短距离 smoothstep 羽化，再乘一次原整体不透明度。该遮罩安装于现有模糊呈现视图，因此 Metal 直出及图像回退共用规则；不修改输入视频色域或 Core Image 半径滤镜，也不把本层遮罩采入下层画面。

布局和调试配置相同则复用已有遮罩，只有尺寸或参数变化才重建静态渐变。继续使用原显示调度与最多两个 GPU 在途槽位，不增加任何逐帧位图遮罩、播放器或动画循环。

配置新增可选 `topFeatherLength`。缺失、非数值及非有限值使用 24pt，有限值限制在 0–80pt；损坏的新字段不能丢弃有效旧层设置。保存沿用原 UserDefaults 键，导出显式包含有效值，全体及模糊层重置恢复 24pt；其他层重置不影响该值。保留原有“重置此层”对半径的历史范围，不顺便改变其他参数。诊断显示选择值与实际生效值，滑块更新不重建播放器或帧来源。

## 测试依据

修复前 [固定测试运行](https://github.com/QingYaoSheep/amll-player/actions/runs/37268215854) 使用真实视频、真实原生呈现层与真实窗口，在捕获的模糊副本中加入受控 12% 白色偏差以确定性复现亮度阶跃；顶部三个视频颜色断言及三个背景颜色断言失败。该受控偏差只存在于新增测试，原始颜色比较使用未经修改的生产输入。468 项单元共 7 条失败断言、8 项 UI 零失败；另 1 条属于既有暂停倒影测试在等待异步重挂载后比较接收计数的竞态，与顶部故障分开记录。将“重放不增加解码接收数”的相同断言移至同步 `replayLatest()` 紧后，再独立等待真实倒影重挂载成功和暂停状态，不改变播放器行为或掩盖新帧接收。

新增数值及真实 CALayer 遮罩检查顶部透明、终点完整、单调、端点平滑、0/24/80pt、10pt 短区域及整体不透明度；新增配置缺失/非法值、往返解码、导出和重置回归。真实窗口还覆盖白/黑、蓝色与肤色背景、倒影开关、实时长度改变、尺寸改变、重复更新复用遮罩、隐藏视频的全背景回退及同一播放器/item/暂停状态。

独立的四项原始真实视频颜色对照显式关闭顶部羽化，保留原无标签/明确 SMPTE170M–709 标签及 item/player 两种输出，容差仍为 3；半径渐变单独回归也关闭羽化。这样新遮罩不能掩盖颜色或半径问题。其余播放、循环、代次隔离、GPU 方向及资源上界沿用现有真实回归。

Windows 本地不提供 Apple 图层运行时，本地静态及 Node 检查不标记为 Apple 视觉测试。原有 13 项未提交歌词/回放文件逐项 SHA-256 核对，独立保留。

候选 `4e3aa26f` 的直接归档及 IPA 检查通过；472 项单元执行完毕有 4 条失败断言，8 项 UI 零失败。三条来自新增基准采样时真实 AVPlayerLayer 尚未上屏：修复后的像素为实际视频 `(201,21,11)`，此前截图却仍为背景 `(102,59,31)`。基准先等待该 fixture 的真实红色列在窗口中可见，再采样；不修改前后 RGB 容差 1 或四项独立颜色容差 3。另一条为 Core Animation 8 位 alpha 栅格化在近透明处的一级抖动 `1→0`：数学曲线新增 257 点严格单调检查，实际渐变允许仅 1/255 的 alpha 抖动，原端点、满不透明度及下方一致性检查保持。生产实现不因这两项观察时序而改变；本次候选的四项无羽化颜色检查、实时背景/倒影矩阵、播放器复用、局部重置及导出已经通过，仍需修正后全套运行确认。
