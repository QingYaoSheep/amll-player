# 沉浸页采样与发热优化

## 设备基线

用户报告 iPhone 16 Pro，Mesh 网格、隐藏歌词并显示竖版动态封面时严重发热和卡顿。当前生产诊断：33.3 FPS；采样 P95 20.87ms；GPU P95 7.16ms；提交等待 P95 0.11ms；帧龄 P95 44.80ms；在途 -1/2。这是用户设备快照，不代表十五分钟热稳定测量。

前一提交等待修复 `d94370f1` 两路 CI 已通过，474 单元／8 UI 零失败，主线程压力下编码到提交由 298.5177ms 降至 0.0151ms。设备现有采样时间仍超出 60Hz 单帧预算，后续优化不改变羽化、模糊半径、分辨率、视频、倒影、层序或歌词。

## 实现

- Mesh 两种取色模式仅在沉浸模糊消费时导出完成帧的 GPU 纹理；同一背景渲染命令附加 blit，不增设播放器或背景绘制循环。普通 Mesh 仍保持 framebuffer-only。
- 四个私有纹理以只读租约管理，完成帧才发布；模糊 GPU 完成前保持输入租约，忙时不覆盖旧帧。尺寸、停用和旧命令发布继续校验代次。原 Mesh 配色、网格、采样尺寸、刷新率及模糊分辨率均未修改。
- 生产下层背景从 GPU 纹理进入同一 Core Image 合成；其他背景与附加层仍走原回退。启动尚无完成纹理时允许旧方式捕获，不按帧排队等待。
- 模糊在进入 UIKit 采样前保留唯一提交身份与代次；各完成／取消路径幂等释放，不再扣减整数计数。已提交工作仍保留到 GPU 完成，维持后台调度保护。
- 双轴审查发现尺寸切换后的旧池会超出总体预算；已改为跨代次共用四个槽位，资源统计包含退役读取者，并补充保留旧帧时连续旋转／停用重启的预算回归。
- 新增实际 drawable 上下方向／颜色检查、输入纹理不可覆盖、池预算、停用迟到命令和采样中配置更新的回归。羽化、倒影比例、暗度、层序和歌词页均保持现有行为。
- 额外颜色检查覆盖两种 Mesh 取色与肤色／蓝绿／紫色封面：冻结真实 hosted Mesh 的同一完成帧，在相同坐标、相同半径和暗度下，比较原 UIKit 捕获与 GPU 共享路径的真实 Metal 呈现；关闭顶部羽化，沿用 RGB 容差 3。审查发现左右不同位置的暗角和抖动不可直接比较，已纠正测试夹具；未改变 shader、原颜色基准或容差。Metal 默认未标记色彩空间，不能仅凭人工红蓝纹理判定宽色域下颜色等价；设备 P3 结果独立验收。

## 验证顺序

1. 背景 CPU 截图开销：共享原背景完成帧的只读 GPU 纹理，观察采样 P95 与读回次数。
2. 在途计数异常：用唯一任务身份释放槽位，避免取消与完成路径重复扣减；验证快速配置、后台与恢复。
3. 其余滤镜开销：前两项验证后再测量；不通过减小模糊半径或关闭动态背景达标。

设备观感、实际持续帧率与发热待复核，自动测试不替代真机热状态验收。
