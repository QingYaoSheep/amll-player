# 歌词动画风格

## 用户行为

“歌词外观 → 动画 → 精细动画调整 → 逐字动画风格”提供 AMLL 和 Apple Music 16.4。
默认 AMLL。两种风格分别保存弹簧、缩放、非当前行模糊、逐字强调、隐藏已播放行、
跑马灯、逐字渐变宽度与提前滚动。首次切换复制当前选项，此后独立保存；重置仅影响
当前风格的动画选项。字体、对齐、真实时间、偏移、音译、背景与 HDR 共用。

Apple Music 16.4 是用户指定的风格名称。本实现依据用户提供的 LyricsBlossom Windows
产物做有限适配，并非 Apple 官方源码或 Apple Music 16.4 的完整复刻。

## 工程接口

- `LyricsAnimationStyle`：可持久化风格标识，未知字符串回退 AMLL。
- `LyricsAnimationProfiles`／`LyricsAnimationOptions`：独立的选项快照；现有扁平字段仍是当前活动值，兼容所有既有设置入口。
- `LyricsAnimationMotion`：集中解析已核实的运动参数，未适配项目复用现有引擎。
- `AMLLRenderEnvironment.animationStyle`：可选回放字段，旧数据缺失时仍为 AMLL。

切换仅重新配置现有引擎参数；保留呈现位置、速度、调度截止时间、焦点状态及逐字时钟。
不改变布局缓存键、不创建新播放器或显示时钟。画布视觉缓存仍通过完整 configuration
比较失效，动态封面及 Plus Lighter 合成路径不变，HDR 上限仍为 1.2。

`FUN_1403a1a00` 整体 UI 顺序由 `DAT_14341ee80=[4,0,1,2,3]` 决定；四个静态标签分别
解码为 16.4、16.4 advance、26.4、27。自定义是六字段不匹配任何表行的派生状态。
背景选项原标签为 16／26；缩放和强调为 16.4／26.4。逐词菜单顺序为 16.4、26.4、27、关闭，
对应存值 0、1、3、2。`FUN_1403a1a00` 的字符串区间依次为 local_348、local_328、
local_308、local_2e8；最后一项由本地化 ID 0x36 取得。`FUN_14018fec0` 将该 ID 映射至
`FUN_140198550 → FUN_1401cf170`（解码 Off）及 `FUN_1401a0ba0 → FUN_1401b9940`
（解码“关闭”）。这也确认了 27 预置的原始逐词存值 3 对应正常菜单“27”。

更新总表里两处机制解释有误，已在原生接口纠正：

- `get(0x1e)` 的 2↔3 仅用于菜单索引；`FUN_1403acb40` 将原始 0...3 直接写入 renderer `+0xb3c`。
- `get(0x20)` 对应截图的**选择句逻辑**：存值 3→菜单 0（16.4），0→菜单 1（advance），1/2→菜单 2（27）；`FUN_140323270` 更新 renderer `+0xb44`。
- `get(0x22)` 对应 **2／3 行控制**，`FUN_1403acb40` 写 `renderer +0xb50=(stored>0)+2`。
  因而 `(v!=0)+1` 既不是实际高亮行数，也不应把原始版本值交换后送进渲染器。

原生已接入：预置联动与自定义匹配、独立持久化、背景歌词提前准备的版本开关、较新缩放
家族的选中行弹簧（`FUN_140303510` 的 m=1,k=30,c=9 分支）、关闭逐词过渡时的普通行尺度
规则、2／3 行视觉限制及 27 逻辑不限行、较新强调家族的 0.25s 结束包络
（`FUN_1402fb4f0`／`FUN_1402fc010`）。真实演唱状态和词时钟不受行数限制。

范围限制：这不是源程序完整状态机移植。16.4 与 advance 的极端选择时序仍使用已修复的
生产调度，不复现未知 bug；逐词各版本完整亮度包络及自适应求参未完全恢复，相关部分
继续沿用 AMLL。没有采用重建文件中 `lineSwitchEasing(forInternalVersion:)` 的猜测映射。
