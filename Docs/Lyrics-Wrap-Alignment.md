# 多行歌词的软换行对齐

## 范围与依据

2026-11-15，IMG_3128/3129 的续行在逗号后多出一个空格。基于 `1f8d4176` 的 Xcode 27 原生复现（`a5f34800`）确认：338pt 宽、32pt 字号下，两句的断点分别为 UTF-16 10、17；四种来源空格编码的第二行均缩进 6.734375pt。播放、逐字强调和滚动未参与测试。

## 排版处理

- 保留均衡断行及其原始 UTF-16 断点，独立计算绘制范围。仅软换行边界的 U+0020 和 U+0009 不进入绘制。
- 首行及 LF、CR、CRLF、U+2028/2029 后的主动缩进保留；NBSP、全角空格与字体自然边距保留。显式空行保留高度。
- 普通 Core Text 和注音容器复用边界规则；注音仍在容器内居中，片段使用原文范围和原计时。辅助文字使用相同边界处理。
- 清晰及模糊贴图使用同一不可变排版快照，SDR/HDR/run 读取同一组片段；不做逐帧横坐标补偿。TextKit 兼容页保留既有实现。

## 验证与边界

`LyricsWrapAlignmentTests` 覆盖截图两句、四种空格编码、断点保留、2×/3× 同字形像素对照、字体/宽度/风格矩阵、组合字符与 emoji、主动缩进、硬换行、NBSP、RTL/对唱和注音容器；兼容页独立检查。

构建和回归结果记录在交付目录 `Builds/Lyrics-Wrap-Alignment-20261115`。既有动效/界面失败与封面模糊待核查失败单列，不修改断言。真机截图复验仍需安装本次 IPA，不能以模拟器结果代替。
