## 新补齐的证据

| 函数 | 已确认的职责 |
|---|---|
| `1401e5ec0` | 设置构造器 `param_1[0x12]=0x3fd999999999999a`，即 `+0x90` 默认0.4；此前列出的animtree:2158/2554是其他对象的同偏移 |
| `140315c60` | 读取最后选中行开始时间，减now、再减0.5，与设置+0x90严格比较；族2/3、暂停、隐藏、scrubbing、空集合及行/词标志均会阻止成立 |
| `14020a600` | 检查行+0x1b2和任意原始词+0x28；本轮不为这些标志猜业务名称 |
| `1402fde90` | 为已分组的排版词构造run记录；合并相同起止时间，累加词宽+0x78；记录+0/+4是时间，+8是累计空间距离，最后记录设置final标记 |
| `1402fe1f0` | 用真实时间计算累计距离目标，再更新run游标；存在线性过渡和另一条指数跟随分支。因此run+0x18是空间游标，不是“run时间” |
| `14031f0f0` | seek重置每个run的游标、过渡和索引；不改变原词时间 |
| `14031ed40` | 每帧推进词与run；直接调用上述构造器和游标更新器 |
| `14031f940` | 根据布局后的词+0x70与空间游标构造水平shader窗口；三种shader构造处于if/else分支，不能解释成三遍白字相加 |

原始词数组位于行+0x50/+0x58；布局后的词位于+0x68/+0x70。排版函数会按
布局拆分情况改写后者的时间，不能直接把它绑定为当前Core Text的CTRun或按字符
平均拆分。run分组取自布局生成的词组，不能只按相同时间重建完整分组。

直接从同一SHA的PE常量池复核：窗口宽30、末端偏移2、min搜索初值10000、
非final的额外窗口系数0.5/0.25/0.12，final为1；指数跟随常量为
0.0833333358。10000是带初值的min归约；空索引仍留下初值，原生安全适配应拒绝
空映射而非画一个巨大窗口。

## 实现与启用范围

- `LyricsBlossomLineSchedule` 建立按源行标志过滤的前缀计数模型，并提供逐帧
  `LyricsBlossomAdvanceState`。不会用末词时间代替选中行时间。
- 生产只接入已确认且无需新对象映射的清零条件：Apple风格暂停时释放已有位置等待，
  保留呈现位置/速度，焦点及退焦已有截止事件同步提前。原AMLL调度不变。
- 原 `.word==1` 清零规则保留。现有普通行错峰仍是本应用调度；源过滤规则和提前
  落地判据尚未绑定生产选择集合，不能称为完整原版选择状态机移植。
- `LyricsBlossomRunSweep` 限定在测试目标，复现已确认的run记录、直接目标分支、
  非负游标和空间窗口；不向发布画布暴露未经验证的坐标换算。
- 生产正文、独立音译及HDR继续读取当前同一份遮罩结果。未将30解释为30pt，
  未添加强制满填充、0.9秒末词截断、三次白字混合或猜测的300ms过渡。
