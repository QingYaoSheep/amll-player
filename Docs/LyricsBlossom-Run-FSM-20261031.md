## 本次已实现

在现有测试目标的`LyricsBlossomRunSweep.Cursor`落地原始游标状态机：

- 普通线性路径、force指数跟随（源Float常量0.0833333358）、原行40/41选路。
- 首次进入中间段读取前段累计宽度；普通补间结束不清空当前索引。
- 最后段仅在`0 < 段右端-cursor < 目标-cursor`时延长时长，最多3倍；
  从force返回的`lastIndex==-2`固定0.25秒，跳过末段延长。
- 越过末段继续旧目标，后续静息时再快照；回到run起点之前清零旧elapsed并归零。
- resync显式接收resetRuns，保留严格`start < effectiveTime`；上层行标志与run生成
  不由这个游标对象猜测。段合并保留累计宽度和非空格UTF-8字节数。

增加10项回归，覆盖60/120Hz与不规则步长、首次中段、同段补间结束、force往返、
末段延长、零时长、超越目标、暂停式零delta、条件resync、等号、raw行选路及Unicode。
这些是按原始控制流构造的数值回归，不冒称原程序事件化轨迹验证。

## 新版交付代码仍存在的翻译差异

- `tickNormal`在普通补间结束后写lastIndex=-1；原函数在这一范围内仅清active。
- 末段时长条件写成`目标-cursor < 段右端-cursor`，方向相反；会漏掉应有的延长。
- 从force回到起点之前时未清elapsed；原函数清零后再消费本帧delta。
- `resync`注释声称有force守卫，但函数仍没有控制输入；原生适配已显式分开。
- `RunGrouping.segments`将distance重置成每组宽度，另外的累计函数没有被它调用；
  且按Swift Character计数。原函数循环按std::string字节步进，并持续累加宽度。
- 报告将词宽写成word+0x54；实际pfVar14位于word+0x24，`pfVar14[0x15]`
  对应word+0x78。不能把指针局部相对偏移直接当作对象偏移。

上述可确定差异已在本项目数值实现中修正，不要求继续重复逆向这些分支。

额外以汇编消除字节计数的反编译类型歧义：构造器`1402fe0c3`起在EDX/EAX做整数
计数，`1402fe0f2`写入记录+0xc；普通分支`1402fe7a4`与force分支`1402fe3d4`
均以整数CMP比较3，不存在浮点转换。因此两分支共用整数UTF-8字节数选择系数，
不能根据伪代码的局部float别名另造一个分支行为。汇编在`run-instructions.txt`。

## 不能据新总结直接启用的结论

1. **画布单位**：renderLine内没有另一个固定DPI缩放，不证明入口CTM、surface尺寸
   与最终呈现缩放恒等。新导出中`140962f60`还有多个其他函数调用者，不能称为
   全进程只在行/词路径调用。报告自身也保留“入口getTotalMatrix待核实”的前提。
   没有实际入口矩阵与目标surface/最终像素对照，不固定30pt或30设备像素。
2. **对象身份**：renderLine的+0x18c属于param5渲染状态，普通行对象另由索引取出。
   该字段的几何缩放用途可确认；“同一个值也控制paint alpha”尚需写入/消费链证明，
   不能用行对象同偏移的采样值替代。+0x7d8等仍须保留独立通道。
3. **颜色**：新日志提供第三站点的一种白色两停靠0.85/0.3样本，支持此分支使用
   渐变而非三遍白字相加；不能推断其他配置与状态全用固定0.85/0.3。
   调用点互斥已从静态代码确认，未命中两处不等于它们的用途是描边/阴影。
4. **分组**：源向量元素到run、相同时间片段到段的消费规则已知；源向量本身怎样由
   换行/方向/样式及源词索引生成，仍未给出完整生产条件，不能直接等同CTRun。
5. **动态输入**：最新颜色断点记录仍不含游标逐帧now/dt/force/row40/41/lastIndex/
   suppressed及暂停/seek事件。函数模型已实现，不代表动态选择路径与原程序对照通过。
