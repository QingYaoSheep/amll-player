## Swift 与原始控制流的实质差异

| 项目 | 原始函数 | 提供的Swift/报告 |
|---|---|---|
| force非零 | `1402fe1f0`的独立指数跟随分支，更新`lastIndex=-2`并重置多项状态 | 完全未实现；`tick`也没有对应输入 |
| 首次进入中间段 | `base + idx*0x14 - 0xc`读取的是**前一段**的distance | 第100行读取`segments[idx].distance`，提前到当前段右端 |
| 末段时长 | 只在剩余距离>0且小于总行程时缩放；非正时长回退1；`lastIndex==-2`另用0.25 | 对非零分母普遍计算比例，且人为使用`1e-4`下限 |
| 越过末段仍在移动 | 沿当前from/to继续推进，并重置lastIndex | 第140行先覆盖to，再推进；未恢复lastIndex |
| 时间退到run之前 | 存在`lastIndex==-2`返回零目标的0.25秒过渡，且继续推进已有运动 | 没有对应分支 |
| resync启用条件 | 只有param4非零才重置/快照；未建run且底层数据为空时跳过；入口还设置row41并应用row40的前瞻 | 无条件清空/快照，且没有相应的控制输入；不能直接绑定所有seek/重排事件 |
| resync的时间等号 | `14031f0f0`选择`segment.start < now` | 第163行使用`<=`，恰好落在词起点时会多跳一段 |
| 行入口简化分支 | `!flag40 || flag41 || force`走主更新；其else才是简化推进 | 报告第3节把`flag40==0`写成简化条件；Swift注释另一处却写对，二者矛盾 |
| 系数单位 | `0.5/0.25/0.12 × 30 + distance`构造**空间目标** | 多处称为0.25秒/0.12秒，量纲错误；0.25只在另一个`lastIndex==-2`时长分支兼作时间常量 |

数值反例（按原始C分支静态求值，不冒称运行时重放）：两段累计距离60/100，
首次进入第二段，末段长1秒。原函数从前段右端60起步，目标130，时长1.75秒；
提供的Swift从100起步，目标130，时长1秒。两者会产生明显不同的填充轨迹。
